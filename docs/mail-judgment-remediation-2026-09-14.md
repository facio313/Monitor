# 메일 위험 판정 수정 — 2026-09-14

## 수정한 문제

정기 메일은 제목을 활성 관측 목록으로, HTML 위험 배지를 순간 지표로
따로 계산했다. 이 때문에 활성 사건이 0건이어도 TCP 순간값 하나로
제목은 ‘정상’, 본문은 ‘위험’이 될 수 있었다. CPU 95% 최초 관측도
지속 조건을 충족하기 전에 정기 메일을 위험으로 만들었다.

`notification_reports.py`, `notification_visuals.py`의 판정을 통합했다.

- 제목·일반 텍스트·HTML은 같은 판정 결과를 사용한다.
- 순간값과 확정 전 관측은 참고값으로 표시한다. 전체 위험은 확인된
  미해소 위험 사건이 있을 때만 표시한다.
- TCP 카드와 텍스트는 기존 알림과 같은 실제 카운터 합산 구간을 사용한다.
  표본이 부족하면 순간 비율로 대체하지 않는다.
- 기존 SMTP 경로에서 제외된 TCP/HTTP 지연 규칙을 정기 메일로 되살리지 않는다.
- 주의에서 위험으로 올릴 때도 기존 지속 조건을 확인한다.
- 위험에서 주의로 개선되면 새 관측 2회·60초로 확인 후 하향한다.
  예전에 위험 메일을 보냈다는 이유로 위험 등급을 계속 유지하지 않는다.
- 전체 조건 해소는 기존대로 정상 관측 2회로 확인한다. 수집 누락은 복구가 아니다.
- 위험 해제 확인 중 CPU가 80%이면 관측 카드는 주의이며, 마지막 확인 사건의
  위험 등급과 현재 관측값을 구분한다.
- ‘주의 1, 위험 8 기준 초과’처럼 두 기준을 모두 넘은 것으로 읽히던 문구는
  ‘판정 기준: 주의 1 / 위험 8’로 바꿨다.
- 미리보기도 공개 관측 목록이 아니라 기존 비공개 판정 체크포인트를
  읽기 전용으로 사용한다. 미리보기에서 발송·설정 변경은 하지 않는다.

수신자·SMTP 비밀값·발송 주기·기존 발송 기록·중복 방지 식별자는 바꾸지 않는다.
새 서버 장애 대응이나 대시보드 판정 전체 개편은 이번 변경에 포함하지 않는다.
재부팅 정책은 유지했고, `wgang` 관련 운영 대상은 제외했다.

## 검증

격리된 입력으로 순간 CPU/TCP 급등, 지속 위험, 주의→위험 승격,
위험→주의 하향, 캐시 재평가, 관측 공백, 복구, 억제된 재발 메일,
출처 손실, 규칙 발송 경로 제외, 읽기 전용 미리보기를 검증했다.
실제 SMTP를 호출하지 않고 제목·텍스트·시각 모델의 등급 일치를 확인했다.

최종 전체 테스트는 저장소 소유자 `cks` 계정으로 실행했다.
`python3 -m unittest discover -s ops/tests -p 'test_*.py'`:
668개 실행, 성공, 환경 조건에 따른 1개 건너뜀. 이 가운데 독립적인
메일 판정 회귀 테스트 9개는 생산자·큐에 고정된 메일·읽기 전용 미리보기를
통해 제목/텍스트/HTML 판정 일치와 등급의 양방향 전환을 확인한다.
