## 근거와 정책 선택의 구분

재현으로 확인한 오류는 HTTP 오류 건수/비율의 등급 역전, DNS 실패에서
인증서 오류를 추론하는 의존 관계, 제한된 프로세스·systemd 관측의 정상 처리,
정상 컨테이너가 목록에서 사라졌을 때 기대 대상을 잊는 동작이다.

HTTP 5xx는 기존 `19/19 → 주의`, `20/100000 → 위험`을 수정했다.
현재 위험 진입은 `3건 이상 AND 50% 이상` 또는 `5건 이상 AND 5% 이상`이다.
그 외 실제 5xx는 주의로 남긴다. 1–2건만으로 서비스 전체 장애를 확정하지 않는다.
4xx나 차단된 SSH 인증 시도는 건수만으로 침입 성공 또는 위험으로 승격하지 않는다.
SSH 즉시 주의 메일의 최소 5건 조건과 기존 중복 억제는 유지한다.

다음 숫자는 기존 규칙과 일관성을 맞춘 **운영 정책**이다. 장기 부하 자료나
서비스별 SLO로 최적값임을 입증한 것은 아니며, 실제 반복 사례로 재조정할 수 있다.

| 자원 | 주의 진입 | 위험 진입 | 주의 / 위험 해제 경계 |
| --- | --- | --- | --- |
| CPU 사용률 | 90%, 5표본·240초 | 사용률만으로 승격하지 않음 | 80% / 해당 없음 |
| 메모리 사용률 | 80%, 5표본·240초 | 90%, 3표본·120초 | 75% / 80% |
| 온도 | 80°C, 3표본·120초 | 85°C, 3표본·120초 | 75°C / 80°C |
| 디스크 사용률 | 85%, 5표본·240초 | 95%, 3표본·120초 | 80% / 90% |
| inode 사용률 | 85%, 5표본·240초 | 90%, 3표본·120초 | 80% / 85% |

해제·등급 하향도 서로 다른 3표본·120초를 확인한다. 순간 하락, 캐시,
관측 누락은 복구 증거가 아니다. CPU/load/I/O 압력은 성능 경합으로 주의를
주되 이것만으로 가용성 장애를 확정하지 않는다. 메모리 some PSI 10%의
지속 위험, 실제 저전압·OOM·링크 단절·읽기 전용 파일시스템 등은 유지한다.

호스트 CPU PSI full은 시스템 범위에서 정의되지 않으므로 판정에서 제외한다.
기존 해당 사건은 정책 정정 이력을 남기며 가짜 복구 메일을 보내지 않는다.
[Linux 커널 PSI 문서](https://docs.kernel.org/accounting/psi.html)

온도 경계는 Raspberry Pi의 80–85°C 열 제한 설명을 참고했다. 온도 한 번의
상승을 하드웨어 고장으로 단정하는 기준은 아니다.
[Raspberry Pi 하드웨어 문서](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)

## 탐지와 관측 범위

- 합성 HTTP 점검: 1분 주기. DNS·timeout·HTTP 실패는 2초 후 1회 재확인하고
  최종 결과만 게시한다. 매 시도 주소 검증과 SSRF 차단을 그대로 수행한다.
  TLS 오류는 실제 TLS 연결/검증 실패로 표시하며, DNS 실패를 인증서 오류로
  겹쳐 알리지 않는다. 최종 표본 시각을 사용해 캐시로 연속 실패를 만들지 않는다.
- 합성 성공 2개로 복구 확인한다. 통상 약 2분이며 실행·수집 시각에 따라 늘 수 있다.
  서비스 전체 시간 상한 40초, 종료 정리 5초, 동시 실행 최대 4개를 유지한다.
  현재 범위 내 설정은 1개 대상, 개별 timeout 10초다.
- 컨테이너: 이전에 정상 관측한 대상은 기대 대상으로 유지한다. 최신·완전한
  목록에서 실제로 사라진 경우에만 기존 ContainerDown 지속 조건을 적용한다.
  수집 실패/캐시/중복 이름 목록은 모든 서비스가 꺼졌다는 증거가 아니다.
  명시적 폐기 대상은 제외한다. **한 번도 관측하지 못한 대상까지 아는 것은 아니다.**
- 제한된 `/proc`는 부분 관측이다. 관측 좀비 0개나 PID 1개를 호스트 전체
  정상으로 해석하지 않는다. 더 넓은 권한을 부여하지 않는다.
- systemd cgroup fallback은 부분 관측이며 실제 Result/NRestarts가 불명이면
  정상·복구나 재시작 횟수를 만들지 않는다. manager 기반 성공 oneshot은 정상이다.
- 외부 감시: **미구축**. 전체 서버 정지·전원 차단 때 이 서버는 메일을 보낼 수 없다.
  매시간 본문에 이 한계를 명시하지만, 미구축 자체를 현재 위험 사건으로 만들지 않는다.
