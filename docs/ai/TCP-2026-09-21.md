# TCP 반복 경고 원인 분석·조치

## 요청·완료 조건
관리 SSH에서 반복되는 TCP 재전송을 분석하고, 해당 현상 때문에 주의/위험
메일이 반복되지 않도록 운영 반영한다. 실제 손실/가용성 장애 알림은 유지한다.
기존 미커밋 작업과 배포 상태를 보존하며 제외 서비스는 작업하지 않는다.
초기 조치에서는 커밋/푸시가 범위 밖이었으나, 후속 요청으로 TCP 관련 변경의
커밋/푸시가 승인됐다. 아래의 미수행 기록은 각 배포 당시의 이력이다.

## 소스 반영 범위
대상 브랜치: `fix/tcp-verified-ssh-20260921`.
main/dev 푸시는 자동 배포를 시작하므로, 다른 미커밋 운영 변경을 덮어쓰지 않도록
이번 TCP 변경만 별도 브랜치로 게시한다. TCP와 무관한 서비스/SSH 국가 분류/메일
설정 변경은 작업 폴더에 그대로 두고 커밋하지 않는다. 서버별 소켓 고정 설정과
운영 데이터도 저장소에 포함하지 않는다.
게시할 인덱스만 별도 임시 트리로 추출해 Python 153개(범위 제외 9개), UI/API 121개,
클라이언트/서버 타입 검사 및 빌드를 모두 통과했다. 따라서 기존 미커밋 작업에
기대지 않는 TCP 변경임을 검증했다. main 병합과 자동 운영 배포는 이번 범위에 없다.

## 재검토 후 연결별 범위 축소 — 승인·배포·실제 경고 해제 확인 완료
사용자가 서버 전체 합계 보정의 안전성을 질문했고, 합계는 같은 연결·패킷에 대한
대응을 보장하지 못함을 확인했다. 이번 사건 해제와 장기 보정 정책의 안전성을
구분하고, 사용자의 후속 승인에 따라 확인된 관리 SSH 소켓 하나로 범위를 좁힌다.
아래 초기 구현/배포 내용은 이력이며 현재 수정 중인 정책과 구분한다.

- 명시적으로 확인한 소켓의 boot ID·커널 cookie·양쪽 endpoint를 해시로 고정한다.
  실제 IP/접속자 포트/cookie는 출력·설정·진단 이력에 저장하지 않는다.
  SSH 리스닝 포트만 조회 필터로 설정하며 신규 연결은 자동 승인하지 않는다.
- 해당 소켓의 TCP_INFO 재전송/DSACK 증가량만 보정에 사용한다. 호스트 TLP/DSACK는
  상한/보조 조건일 뿐, 더 이상 보정량의 출처가 아니다. 다른 연결의 재전송은 남긴다.
- 호스트 카운터 읽기 전후에 소켓을 조회하여 두 관측 사이의 안쪽 구간만 계산한다.
  재접속/재부팅, 관측 누락, 카운터 초기화, 다른 구간의 DSACK는 보정하지 않는다.
- 기존 손실 지표/신선도/최소 표본/2회 해제 조건을 유지한다.
- 보정은 동일 소켓의 누적 통계에 근거한 보수적 추정이며, 모든 패킷의 시퀀스와
  DSACK를 일대일 대응해 손실 부재를 증명한 수치는 아니다. 원시 이력을 유지한다.
- AF_NETLINK 추가는 별도로 요청해 사용자 승인 후 01:05 KST에 적용했다.
  AF_UNIX/AF_NETLINK만 허용하며 AF_INET/AF_INET6·CAP_NET_ADMIN은 추가하지 않았다.
  조회 실패 시 원시 수치로 판단한다.
- 연결별 정책/수집 회귀 18개 포함 Python 150개 통과(제외 서비스 사례 9개 미실행).
  UI/API/운영 판정 121개 통과. 새 API 거부 테스트의 예상 상태를 기존 계약인
  collection_error로 바로잡아 해당 파일 16개를 재검증했다(나머지 105개 통과 유지).
  클라이언트/서버 타입 검사와 Node 22.23.2 빌드 통과. 기존 대형 JS 청크 경고만 존재.
  승인된 주소군 변경 후 systemd 단위 회귀 3개 추가 통과(총 Python 153개).

## 구현 계획
1. 기존 SNMP 수집에 TLP/DSACK/실제 손실 복구 관련 카운터를 추가한다.

   TLP·DSACK의 공통 최소 건수를 중복 탐색 재전송 추정치로 보정한다.
   호스트 합산 추정이지 개별 패킷의 유실률 계산은 아니다.

## 초기 정책의 한계 (이후 위의 연결별 정책으로 대체)
TLP와 DSACK는 호스트 누적 카운터이며 개별 패킷 대응 관계를 증명하지 않는다.
보정치는 최소(TCP 재전송, TLP, DSACK)로 제한한 운영 판단용 추정치다.
타임아웃/SYN 재전송/빠른·느린 재전송/손실 탐색 복구/송신 실패 중 하나라도
증가하면 해당 창은 보정하지 않는다. 근거가 없거나 초기화된 경우도 원시 판정이다.
원시 데이터/진단 이력은 유지하며 실제 서비스 장애 신호도 그대로 평가한다.
PC의 ACK 지연 자체를 제거하거나 모든 TCP 재전송을 0으로 만든 변경은 아니다.
원격 커밋/푸시는 하지 않았으므로 이후 원격 자동 배포가 로컬 이미지 변경을 덮을 수 있다.

참고: [RFC 8985의 지연 ACK와 TLP](https://www.rfc-editor.org/rfc/rfc8985.html#section-9.4),
[Linux SNMP 카운터](https://docs.kernel.org/networking/snmp_counter.html#dsack).
